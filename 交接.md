# 作业助手交接

一份部署对应一个班。学委发布作业，全班在时间线里看进度。用户实际用的是安卓原生界面。电脑端源码要跟着改，但不要把新构建覆盖到已经发布的网站上。

手机已安装 versionCode 24，包名 `edu.hust.homeworklogistics`。安装包与中转路径均为本机临时文件，不入库。

作业详情里，「我的进度」不再有备注栏。评论区在进度下面：全班都能发文字，一条评论最多 4 张图片。自己的评论可以删，学委可以删任何一条。评论表还没在云上执行时，进度照常可用，评论区会提示还没建表。

## 现在的界面

发布作业要填四项：

- 科目：下拉，名单由学委在个人页的「科目管理」里添加、删除
- 周次：数字，显示成「第 13 周」
- 说明
- 截止时间：年、月、日、时、分五个下拉，新作业默认今天 23:59

作业标题就是科目。主页卡片写成「高等数学（第13周）」，下一行是截止日期和发布人，中间不用点隔开。说明和图片要点进详情才显示。

进度是揽收流程：未写完 → 已写完，随时可以提交 → 学委已揽收 → 学委已取回 → 学委已分发。每一步能看时间。揽收按人勾选。取回和分发是全班一次操作，在作业管理里点「全班取回」「全班分发」。

学委个人页：作业管理、科目管理、转让学委、成员管理。成员管理里可以删除非学委成员。

## 还没在云上确认的事

应用代码不会执行建表。下面的语句如果还没交给 WorkBuddy 执行，对应功能会失败。只执行追加语句，不要重跑整份 `schema.sql`，不要 `DROP TABLE`，不要 `TRUNCATE`，不要重新发布网站。

科目和周次还没建好时，发布会提示「科目和周次还没写进云数据库」：

```sql
CREATE TABLE IF NOT EXISTS public.subjects (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  owner_id TEXT NOT NULL DEFAULT auth.uid(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

ALTER TABLE public.assignments ADD COLUMN IF NOT EXISTS week TEXT NOT NULL DEFAULT '';

ALTER TABLE public.subjects ENABLE ROW LEVEL SECURITY;
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.subjects TO authenticated;
DROP POLICY IF EXISTS subjects_select ON public.subjects;
CREATE POLICY subjects_select ON public.subjects FOR SELECT TO authenticated USING (true);
DROP POLICY IF EXISTS subjects_insert ON public.subjects;
CREATE POLICY subjects_insert ON public.subjects FOR INSERT TO authenticated WITH CHECK (owner_id = auth.uid() AND public.current_class_role() = 'monitor');
DROP POLICY IF EXISTS subjects_delete ON public.subjects;
CREATE POLICY subjects_delete ON public.subjects FOR DELETE TO authenticated USING (public.current_class_role() = 'monitor');

GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO authenticated;
NOTIFY pgrst, 'reload schema';
```

全班取回、全班分发要等 `enforce_submission_status` 换成 `schema.sql` 里现在的函数，否则云端返回「现在不能改这一步」。删除成员要等 `profiles_delete` 策略。这两段都已经写在项目根目录的 `schema.sql` 里，是否已在线上执行过不确定。

作业评论还没建表时，详情页进度仍可用，评论区会提示「评论还没写进云数据库」。只执行下面这一段：

```sql
CREATE TABLE IF NOT EXISTS public.comments (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  assignment_id BIGINT NOT NULL REFERENCES public.assignments (id) ON DELETE CASCADE,
  body TEXT NOT NULL DEFAULT '',
  owner_id TEXT NOT NULL DEFAULT auth.uid(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS public.comment_images (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  comment_id BIGINT NOT NULL REFERENCES public.comments (id) ON DELETE CASCADE,
  storage_path TEXT NOT NULL,
  owner_id TEXT NOT NULL DEFAULT auth.uid(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

ALTER TABLE public.comments ENABLE ROW LEVEL SECURITY;
GRANT SELECT, INSERT, DELETE ON TABLE public.comments TO authenticated;
DROP POLICY IF EXISTS comments_select ON public.comments;
CREATE POLICY comments_select ON public.comments FOR SELECT TO authenticated USING (true);
DROP POLICY IF EXISTS comments_insert ON public.comments;
CREATE POLICY comments_insert ON public.comments FOR INSERT TO authenticated WITH CHECK (owner_id = auth.uid());
DROP POLICY IF EXISTS comments_delete ON public.comments;
CREATE POLICY comments_delete ON public.comments FOR DELETE TO authenticated USING (owner_id = auth.uid() OR public.current_class_role() = 'monitor');

ALTER TABLE public.comment_images ENABLE ROW LEVEL SECURITY;
GRANT SELECT, INSERT, DELETE ON TABLE public.comment_images TO authenticated;
DROP POLICY IF EXISTS comment_images_select ON public.comment_images;
CREATE POLICY comment_images_select ON public.comment_images FOR SELECT TO authenticated USING (true);
DROP POLICY IF EXISTS comment_images_insert ON public.comment_images;
CREATE POLICY comment_images_insert ON public.comment_images FOR INSERT TO authenticated WITH CHECK (
  owner_id = auth.uid()
  AND EXISTS (
    SELECT 1 FROM public.comments AS comment
    WHERE comment.id = comment_id AND comment.owner_id = auth.uid()
  )
);
DROP POLICY IF EXISTS comment_images_delete ON public.comment_images;
CREATE POLICY comment_images_delete ON public.comment_images FOR DELETE TO authenticated USING (owner_id = auth.uid() OR public.current_class_role() = 'monitor');

GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO authenticated;
NOTIFY pgrst, 'reload schema';
```

## 不要动的东西

- 不要删 `server/data/app.db`，也不要删它的 WAL、SHM。本地旧数据不迁移，文件要留着。
- 不要卸载手机应用。更新用 `adb install -r`，并提高 `versionCode`。签名文件是 `mobile/app/release.keystore`（不入库），别名与密码见本机 `mobile/app/keystore.properties`——不要把密码写进任何文档或提交。
- 不要用新的 Vite 构建覆盖 `homework-app/public`。线上登录页有微信和手机号验证码，源码 `desktop/src` 里还没有这两项，覆盖会把登录退回只有 WorkBuddy。
- 不要改线上地址、appId、启动命令。页面地址必须带 `sharecode=3NIEKUN3F6`。PostgREST 请求不要把 sharecode 放到查询参数里，否则会 400。
- 不要动学委那个账号（学号见云端 profiles 表，不写进仓库）。登录是网站 WebView，进去后读 localStorage 会话，再用 Kotlin 调云数据库。
- 客户端不要提交 `owner_id`，由数据库默认成当前用户。
- 用 PowerShell 发中文请求会把字变成问号，要用 UTF-8。截屏不要用 PowerShell 重定向，用 `cmd /c adb exec-out screencap -p > <临时目录>/phone.png`。这台小米上 `adb input tap` 会被拒绝。

## 代码在哪

- 手机界面：`mobile/app/src/main/java/edu/hust/homeworklogistics/MainActivity.kt`
- 手机云接口：同目录 `CloudApi.kt`
- 进度规则：`Domain.kt`，与 `desktop/src/domain.js` 对齐
- 电脑端数据：`desktop/src/api.js`、`desktop/src/App.jsx`
- 表结构：项目根目录 `schema.sql`，WorkBuddy 目录里也有一份追加过的副本
- 云配置：`desktop/src/cloudConfig.js`。密钥已经写在源码里，不要再打印出来。

发布目录是 `<发布目录>`。线上页面：`https://homework-assistant-14264.app.workbuddy.host/`。

## 装到手机

在 `mobile` 目录：

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat assembleRelease --offline
```

然后把 apk 复制到 `<临时目录>/app-release.apk` 再安装。中文路径直接安装会失败。

```powershell
adb install -r "<临时目录>/app-release.apk"
```

装完后同步复制一份到桌面 `<repo>/app-release.apk`。
