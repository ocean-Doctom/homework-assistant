# 开发流程

> 目的只有一个：**减少返工**。今晚的教训是"功能都做出来了，但每样都要改三遍才稳"。

---

## 一、每次改动，四步走

### 1. 动手前（3 分钟，最重要）

回答三个问题，写进回复里：

- **影响谁**：这个改动会让哪些已有功能受影响？（作业列表 / 评论 / 私聊 / 登录）
- **老数据怎么办**：加字段要不要回填？改策略会不会让老客户端挂？
- **怎么验**：改完之后，用什么具体操作能证明它是对的？

> 今晚"输入条"改了 4 版、"课程"字段加了又删，都是跳过这一步的代价。

### 2. 改的时候

- **一次只改一件事**。不要在一个提交里同时改 UI 和数据库。
- **破坏性操作单独说**：删数据、改 RLS、改表结构，先说明影响再动手。
- **不确定的需求先问**，不要猜。猜错的成本是整轮返工。

### 3. 改完自检（五条，逐条过）

- [ ] 新功能主路径能走通
- [ ] 老功能没坏（至少点一遍主页、评论、消息）
- [ ] 空数据不崩（没有作业 / 没有评论 / 没有消息）
- [ ] 异常有提示（断网、权限不足、超时）
- [ ] 换个屏幕尺寸还行（手机 + 网页 512 宽）

> 今晚"班级空间忘加白底"、"三个菜单图标撞车"、"会话列表不读头像"，都是没走这一步。

### 4. 提交

```bash
git add -A
git commit -m "动词 + 对象：一句话说清改了什么"
```

提交信息用这个格式，让人一眼看懂：

```
新增：解散班级（学委，空班才允许）
修复：注册时 RLS 拒写（策略子查询自锁）
调整：输入条改为内嵌，加号 44→40dp
```

## 二、数据库改动（最高风险，单独一节）

今晚数据库改了 20 多次，**导致 3 次注册失败**。所以这块流程最严：

### 改之前

1. **先查现状**：`SELECT` 一遍相关数据，确认影响范围
2. **想清楚顺序**：加字段 → 回填 → 设 NOT NULL → 加约束，不能跳
3. **函数依赖**：函数体引用某列时，那列必须先存在

### 改的时候

- **加字段一律先 nullable**，回填后再 `SET NOT NULL`
- **策略改动用 `DO $do$ ... END $do$` 包起来**，失败整体回滚，不留半成品
- **不要在同一条策略里子查询被同一策略保护的表**（会自锁），改用 `SECURITY DEFINER` 函数

### 改之后（必须做）

1. **立刻验证**：`SELECT` 查一遍关键数据，确认写入正确
2. **两端都要试**：安卓 App 和网页用的可能是不同的客户端代码，任何一个没改都会挂
3. **记进 `migrations/`**：函数、触发器、策略的完整定义，能照着重建

> 详细案例见 `migrations/2026-11-26-class-isolation.md` 的"踩过的坑"。

## 三、发版流程

### 安卓

```bash
# 1. 升版本号（app/build.gradle.kts）
versionCode 加 1，versionName 改掉

# 2. 编译
JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew assembleRelease

# 3. 复制到发布目录 + 桌面
cp app/build/outputs/apk/release/app-release.apk <发布目录>/public/app-release.apk
cp app/build/outputs/apk/release/app-release.apk ~/Desktop/作业助手.apk

# 4. 改 version.json 的 versionCode（必须和 APK 一致，否则更新提示会死循环）

# 5. 发布
```

**验证**：`curl <地址>/version.json?sharecode=...` 返回的 versionCode 要和刚编的一致。

### 网页

```bash
cd desktop && npm run build
cp dist/assets/* <发布目录>/public/assets/     # 先删旧的 js/css
cp dist/index.html <发布目录>/public/index.html
# 发布
```

**注意**：网关要求所有地址带 `?sharecode=3NIEKUN3F6`，否则 403。

## 四、和 AI 协作的约定

- **需求模糊时先确认范围**，不要直接动手做一版再问
- **改动前说明影响面**，尤其是数据库和 RLS
- **改完主动说"哪里没验证"**，不要用"已完成"掩盖未验证的部分
- **同一件事不要重复返工**：第一次做就要问清楚尺寸、文案、边界情况
